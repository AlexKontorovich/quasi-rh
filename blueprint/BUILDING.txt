Interactive blueprint
=====================

The site uses Verso's Lean-to-HTML renderer inside the original custom page
design. This is a Verso-backed HTML composition, not a Verso Manual document:
the mathematical prose and layout stay in page.html; every Lean panel comes
from an elaborated source module, not syntax-colored text or invented hovers.
No mathematical source was changed for this migration.

Author prose/layout in blueprint/page.html, not generated index.html.
Author colors, spacing, typography, and responsive layout in blueprint/theme.css;
Lean-panel styling lives in blueprint/verso.css. Keeping cosmetic edits in these
files enables the fastest deployment path.
Author Lean in its original .lean file. Run scripts/sync-blueprint.mjs after
editing declarations displayed by a source-synchronized panel. Other panels
are resolved by declaration name at site build time; ambiguous names fail.
The two formerly schematic panels now show the actual complete statements.

Build from the repository root:

  lake exe cache get
  npm ci --ignore-scripts
  node scripts/sync-blueprint.mjs
  node tests/sync-blueprint.test.mjs
  node scripts/build-blueprint.mjs
  node tests/verso-blueprint.test.mjs

Output is _site/, including index.html, linked module pages, Verso's JavaScript,
styles, search data, and shared hover table. Serve the WHOLE directory over
HTTP; opening just index.html as a file cannot load the JSON hover database.
The generated index is also saved to blueprint/index.html for review.

The Pages workflow first checks an exact finished-site cache. CSS-only edits
restore that validated site and copy the two current CSS files into it, skipping
Node setup, npm, Lean, composition, and tests. Upload and Pages rollout remain.
New pushes cancel superseded workflow runs instead of waiting behind them.
The finished-site key includes prose, Lean, dependencies, renderer, and tests,
but not CSS. Cache misses fall back to the normal validated rendering pipeline.

The Pages workflow also has a Node-only fast path for prose and HTML edits.
It restores raw Verso pages and compiler declaration metadata from a small
presentation cache, then composes, validates, and deploys the current page.
It does not install Lean, restore oleans, or run Lake on a presentation-cache hit.
The exact cache key includes Lean sources, dependency pins, the toolchain,
and the set of displayed modules. There is no stale-key fallback.
On a cache miss it fetches Mathlib's cache, builds the selected literate facets,
and runs the pinned verso-html executable. Raw output is cached BEFORE page
composition. The first run with this workflow seeds that presentation cache;
Lean changes, new displayed modules, or cache eviction can require a slow run.

Theorem proofs are omitted from guide panels, but are present on linked
module pages with Verso's proof-state interactions. Shared section context
is preserved where explicitly requested. Other ambient variables can be
inspected via semantic hovers and the complete source page.
